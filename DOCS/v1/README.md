# ShotEasy V1 实现规范

> 状态：规划中，尚未开始实现。

本目录是 ShotEasy V1 的实现依据。V1 的目标不是把项目扩展成完整设计平台，而是在保留当前轻量架构和全部已有能力的前提下，完成编辑体验、视觉布局和一组高价值功能的升级。

## 文档导航

- [产品规格](./product-spec.md)：产品定位、用户流程、界面布局、功能范围和非目标。
- [技术设计](./technical-design.md)：项目文档模型、历史记录、渲染、草稿与公共 API。
- [执行方案](./implementation-plan.md)：里程碑顺序、模块改造、依赖关系和阶段退出条件。
- [执行 TODO](./TODO.md)：唯一任务进度清单。
- [验收标准](./acceptance.md)：已有功能回归、新功能验收、导出和组件兼容检查。

当前实现事实仍以 `DOCS/` 下的现有文档和实际代码为准。本目录描述尚未实现的 V1 目标；在对应 TODO 完成并通过验收前，不得将规划内容写成当前已有能力。

## 文档优先级

发生冲突时按以下顺序处理：

1. 用户对当前任务的明确要求。
2. 本文的“锁定决策”和“变更规则”。
3. [技术设计](./technical-design.md)与[产品规格](./product-spec.md)。
4. [执行方案](./implementation-plan.md)。
5. [TODO](./TODO.md)中的任务描述。
6. `DOCS/` 中描述当前版本的文档。
7. 临时实现偏好或参考产品行为。

如果必须改变锁定决策，应先更新本文，写明变更原因、影响的里程碑、公共 API 和回归范围，再修改代码。

## 锁定决策

| 领域 | V1 决策 |
| --- | --- |
| 技术栈 | 继续使用 React 18、Vite、MobX、LeaferJS、Ant Design 和 Tailwind CSS |
| 产品形态 | 纯浏览器、轻量、单图截图美化编辑器 |
| 构建产物 | 同时保留独立站和 `ImageBeautifier` npm 组件库 |
| 主题与语言 | 独立站默认深色和中文；组件继续遵循现有主题逻辑，界面文案统一为中文 |
| 图标 | 使用 `mage-icons-react`，经项目内部适配层统一输出 |
| 桌面布局 | 顶部全局栏、左侧比例/外框/布局、中间画布、底部标注栏、右侧属性栏 |
| 移动布局 | 画布优先，左右功能收进抽屉或底部面板，核心功能保持可用 |
| 新增能力 | 撤销/重做、本地草稿、富样式文字、模糊、马赛克、聚光 |
| 背景 | 内置图片与本地上传，不接 Unsplash 搜索 |
| 外框 | 保留已有外框，新增 Card、Stack、Stack 2、Glass Light/Dark、Arc 风格、Polaroid |
| 布局预设 | 仅二维：默认、铺满、悬浮、左倾、右倾、底部展示 |
| 草稿 | 独立站默认恢复；npm 组件通过 `persistence` 显式启用 |
| 测试 | 不引入自动化测试框架；必须执行 lint、双构建和完整人工回归 |
| 参考项目 | 只借鉴交互和组织方式，不迁移或 Fork Screenshot Studio |

## 明确不做

V1 不实现以下内容：

- 图层面板及图层排序、锁定、隐藏 UI。
- URL 抓取或网站截图服务。
- Unsplash 搜索 API。
- 登录、注册、账户、会员、付费或云同步。
- 视频、GIF、动画时间线或关键帧。
- 3D 变换、Three.js 或第二套画布引擎。
- 多图画布、幻灯片、多页面或协作编辑。
- 文本卡片、代码卡片等独立内容生成器。
- 后端、数据库、对象存储或服务端渲染。
- TanStack Start、Next.js 或其他应用框架迁移。

## 里程碑

| 阶段 | 目标 | 依赖 |
| --- | --- | --- |
| M0 | 修复开发基线，记录旧功能基准 | 无 |
| M1 | 可序列化项目状态和可靠历史记录 | M0 |
| M2 | 深色三栏布局、中文与图标统一 | M1 |
| M3 | 比例、外框与二维布局预设 | M2 |
| M4 | 新背景系统与轻量背景效果 | M3 |
| M5 | 文字、模糊、马赛克和聚光 | M4 |
| M6 | IndexedDB 本地草稿 | M5 |
| M7 | 全量回归、文档同步与交付 | M6 |

里程碑必须顺序执行。一个阶段只有在其退出条件全部满足并在 [TODO](./TODO.md) 记录验证结果后，才可开始下一阶段。

## 防止开发走偏

- 不得为了视觉优化替换状态管理、画布引擎或构建框架。
- 不得顺手加入“明确不做”中的功能。
- 不得删除或改变已有公共 Props、库入口、导出格式和快捷键。
- 新 UI 必须调用统一的 store action，不能在组件内形成第二份业务状态。
- 新画布能力必须进入可序列化文档模型，不能只存在于 LeaferJS 节点中。
- 所有远程图片必须验证 CORS 和导出；失败时不得破坏当前作品。
- Screenshot Studio 只作为参考。若复用具体代码，必须记录原始文件、提交和许可证要求。
- 每完成一个里程碑，同步更新 TODO 状态和实际验证结果；不能只勾选任务而不记录证据。

TODO 使用以下标记：

- `[ ]`：未开始。
- `[-]`：进行中。
- `[x]`：已完成，且已有验证记录。
- `[!]`：阻塞，必须写明原因和恢复条件。

同一时间原则上只有一个里程碑处于进行中。
